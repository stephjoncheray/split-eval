Informations, confidentialité et protection des données

Principe : Split Eval est une application web statique destinée à préparer localement les restitutions individuelles des évaluations nationales. La version hébergée sur GitHub Pages ne possède ni base de données de campagnes ni serveur de réception des PDF et des fichiers PRONOTE.

Que deviennent les documents importés ?

  • Les PDF, les contacts PRONOTE et les correspondances sont lus et traités dans la mémoire du navigateur, sur l'appareil utilisé. Ils ne sont pas volontairement déposés dans un espace de stockage de Split Eval ou dans le dépôt GitHub.
  • Les fichiers générés (PDF découpés, ZIP de campagne, brouillons Thunderbird au format EML, journal de préparation) sont téléchargés sur votre appareil lorsque vous choisissez de les exporter. Ils peuvent alors rester dans « Téléchargements », les sauvegardes ou les logiciels de messagerie : leur suppression vous incombe.
  • La version web n'expédie aucun courriel et n'archive aucun message dans « Envoyés ». Elle n'établit pas d'envoi SMTP/IMAP. Les demandes de priorité, accusé de lecture et copie dans « Envoyés » sont seulement consignées dans le manifeste de préparation lorsqu'elles sont sélectionnées.
  • Fermer ou recharger la page met fin à la session de travail en mémoire, sans constituer une garantie d'effacement sécurisé des copies, téléchargements, caches, sauvegardes ou journaux techniques.

Connexions et limites de sécurité

Le site est hébergé par GitHub Pages. Les bibliothèques de lecture PDF et Excel sont actuellement chargées depuis le service tiers cdnjs.cloudflare.com : le navigateur contacte donc GitHub Pages et ce fournisseur de scripts. Des métadonnées de connexion (notamment adresse IP, date et navigateur) peuvent être enregistrées par ces services selon leurs politiques. Le code actuel ne prévoit pas l'envoi de vos PDF ou listes de responsables à ces fournisseurs ; néanmoins, l'absence de transmission ne peut pas être garantie face à une bibliothèque tierce compromise ou à une extension de navigateur malveillante. L'auto-hébergement des bibliothèques et un audit de sécurité restent nécessaires avant tout usage institutionnel avec des données nominatives.

RGPD et confidentialité des élèves

Les noms d'élèves, résultats scolaires, coordonnées des responsables et pièces jointes sont des données à caractère personnel. L'utilisation de cet outil doit respecter le RGPD, les instructions de l'établissement et les règles de sécurité applicables aux traitements scolaires. L'absence de stockage sur le site ne suffit pas, à elle seule, à rendre le traitement conforme au RGPD.

  • Utiliser uniquement les données strictement nécessaires aux restitutions et vérifier la base légale, la finalité et les destinataires autorisés dans le cadre de l'établissement.
  • Faire valider l'utilisation de l'outil par les responsables compétents (direction et, selon l'organisation académique, délégué à la protection des données / DPO).
  • Vérifier soigneusement le nom, la classe, les responsables légaux et chaque PDF associé. Un homonyme, une erreur de reconnaissance ou une adresse incorrecte peut conduire à une divulgation de données scolaires.
  • Conserver les exports confidentiels uniquement sur un espace de travail autorisé, limiter les accès et les supprimer après la durée nécessaire ; éviter les ordinateurs partagés, les messageries personnelles et les services de stockage non approuvés.
  • Ne jamais publier de véritables PDF d'élèves, exports PRONOTE, journaux nominatifs ou mots de passe SMTP dans GitHub, même dans un dépôt privé.

Précautions avant toute diffusion

Le ZIP de campagne et les brouillons EML sont des documents sensibles : ils peuvent contenir des adresses et des restitutions nominatives. Leur génération n'est pas une preuve d'envoi. Avant toute diffusion, contrôler les destinataires, les pièces jointes, les exclusions et l'absence de doublons. Les accusés de lecture et notifications de distribution ne sont pas garantis ; un journal d'acceptation SMTP n'atteste pas que le courriel a été lu.

État du projet : outil en développement, dont les dépendances externes et les traitements doivent encore être audités avant une utilisation sur des données scolaires réelles. Cette rubrique décrit le fonctionnement technique constaté, sans constituer une attestation de conformité RGPD.
